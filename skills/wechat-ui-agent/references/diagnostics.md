# wxbot 排查手册（读日志 → 定位 → 处置）

只在用户报"不回消息 / 发不出去 / 读端异常"时读本文件。原则：**先看证据（日志、库、WeFlow 原始消息），再改任何东西**；
对照时间线，别猜。

## 0. 先分清三条路

一条消息要走：**读端（WeFlow）→ 去重入库 → 规则判定 → LLM 生成 → 发送（OCR + 点击）→ 送达核对**。
日志里对应：

| 日志关键字 | 含义 |
| --- | --- |
| `📩 … → 并行(开聊天\|生成回复)` | 读到了、开始处理 |
| `跳过：…` | 规则层没让它回（原因都写在后面） |
| `✅ … 已点击发送（UI 已在聊天区看到这条）` | 发送成功且 UI 自证通过 |
| `❌` | 发送或生成失败（后面会带原因） |
| `后台核对未确认送达` / `[verify_notice] 已给主人留话` | 点了发送但读端没回读，已按"不重发"处理并通知主人 |
| `[看门狗] 窗口=OK 数据源=OK 连续失败=0` | 每约 60s 一条，看到它说明循环活着 |

日志默认打在**标准输出**（面板界面里也能看最近日志）。跑常驻时建议把 stdout 重定向到文件，方便回溯。

## 1. "它不回消息" 检查清单（按顺序）

1. **触发模式**：群里默认 `mention` —— 没 @、没引用、没命中关键词就不回（日志写 `没被 @` / `没命中关键词` / `不是在引用机器人`）。
2. **@ 判据**：群昵称 / 昵称要和 `whoami` 打出来的一致；改了微信昵称后重跑 `whoami`。
3. **时间窗**：`trigger.time_window` 之外的时段不回（日志 `不在静默时段外的时间窗内`）。
4. **限流**：日志 `限流：…`（间隔不足 / 连点合并 / 每小时、每日上限）。调 `limits`。
5. **白名单**：会话不在 `contacts` 或 `enabled: false` —— 根本不处理。
6. **消息过期**：暂停 / 故障积压超过 `ingest.backlog_max_age_seconds` 的消息会被丢弃（防"补回一堆旧消息"）。
7. **防自回环**：日志 `这就是我最近发过的内容，防自回环…` —— 说明读回来的是自己发过的东西，属正常。
8. **非文本**：`trigger.ignore_types` 里的类型（图片/语音等）不回；图片要走视觉理解需要对应档位支持。

## 2. "回了但没发出去 / 发错" 检查清单

- **三层校验拒发**：日志里会有 `列表里没有该会话…` / `匹配到 N 个目标，拒绝发送` / `标题条带未通过校验` / `发送前身份校验失败`。
  依次查：`contacts[].name` 与微信里显示的是否一致（备注 / 昵称 / 群名都认）→ 微信窗口别拖太窄（名字会被截断成"XX…"）→ 跑 `doctor` 会话名体检。
- **失败不重发**：发送阶段失败会记 `sent_unverified`（怕重复发）。这类"可能已发出"的消息**不会自动重发**；
  新版会对"点了发送但读端没回读"的回复给主人留一条私信提示（看 `bot.watch_notify` 指向的会话）。
- **两次独立触发**造成重复：用日志里的 request 对照，不是重试 bug；连点合并靠 `limits.burst_merge_seconds`。
- **发送慢**：稳定态 3–5s；重启后第一单可能 10s+（列表直点第一次不确认会再点一次），这是可靠性取舍。

## 3. 读端（WeFlow / MCP）问题

- `-105` / 连不上 → `doctor --fix`，或单独跑 `工具\repair-weflow.ps1`；确认 WeFlow 在运行且
  `ingest.weflow.access_token` 与它一致。
- SSE 掉线：面板/长跑统计里有 `SSE掉线` 计数；会自愈重连，连续失败会进看门狗计数。
- 想确认"微信里到底有没有这条"：直接问 WeFlow 的原始消息接口（绕过本项目的过滤），
  这是判定"真丢了 vs 读端漏报"的唯一可靠依据。

## 4. 模型问题

- 401 / 超时 → 查对应档位的 `base_url` / `model` / key（key 建议放环境变量，如 `LLM_CLOUD_KEY`）；
  用 `& $py -m wxbot.cli test-llm --profile cloud --text "你好"` 单测某档位。
- 档位回退：`llm.active` + `llm.fallback` 决定顺序；日志 `profile=` 会写实际用了哪档。
- 本地 Ollama：确认服务在 `http://127.0.0.1:11434`，模型名与 `ollama list` 一致。

## 5. 数据与隐私（用户常问）

- 全部数据在 `data\`：`wxbot.db`（消息 / 回复 / 记忆 / 摘要 / 提醒 / 订阅 / own_sent）、`shots\`（截图）。
  表结构见 `wxbot\store.py` 的建表语句；可以用 venv 里的 python 直接查 sqlite。
- 保留策略：`audit.messages_keep_days` / `audit.shots_keep_days` 等（`replies` 默认 180 天）。
- 记忆分"个人 / 群"两份：私聊说的只进那个人的个人记忆；A 群说的不进 B 群（有离线探针钉住这条边界）。

## 6. 运行控制

- 停止：面板"停止"或 Ctrl+C；**不要在任务管理器强杀**（正在发送的消息会留下 `sent_unverified`）。
- 同一时间只允许一个进程操作微信界面（单实例锁）；重复启动会被拒绝 —— 这是特性，不是 bug。
- 面板打不开：用它启动时打印的**带 `#token=` 的完整地址**；换端口 `--port 8899`。
